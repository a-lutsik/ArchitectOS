# Изоляция памяти между проектами: план и статус

Цель: агент одного проекта не должен видеть и не должен менять память другого
проекта. Это касается и prompt injection: модель не может ни прочитать чужой узел
по id, ни переключить проект, ни переписать чужое знание. Требование относится ко
всем входам: MCP-серверу, хукам агентов, AI-ранам через tool gateway, HTTP с
`project_id` и SDK.

## 1. Правило видимости (чтение)

- Единое правило — `MemoryEmbeddingEngine._passes_scope_filter` / `node_visible`
  (`backend/architectos/embeddings.py`). Его SQL-копия —
  `storage_search.scope_visibility_sql`. Оба правила должны меняться вместе.
- Проекту видны свои узлы, узлы без `project_id` и узлы со scope `shared`/`global`.
  Узлы `project_shared`, `user_private` и `interface` чужого проекта скрыты.
- Явный `scope` в поиске только сужает выдачу по сравнению со `scope=None` и
  никогда её не расширяет.
- Скрытый id неотличим от несуществующего: тот же текст ошибки и тот же
  `hit_count`, у скрытых узлов нет побочных эффектов (событий, lifecycle). Id
  скрытых узлов вырезаются из metadata, истории, хитов, stable- и rule-слоя,
  briefing и graph-ответов. Хранилище при этом не меняется.

## 2. Правило записи (владение)

Решение пользователя: если у записи есть **проект вызывающего**, ничто вне его
владения не меняется. Под запрет попадают SUPERSEDES, enrich, fold, evidence,
confidence, metadata и события чужого узла. Вместо изменения создаётся новый узел
со ссылкой `possible_duplicate_of`. Если активный чужой узел уже содержит тот же
факт, запись получает held и ничего не пишет. Свой узел проект по-прежнему может
заменить, обогатить и оживить. Без проекта вызывающего (несвязанный сервер,
HTTP/UI без проекта, внутренние compaction и dedup) поведение прежнее.

- Владелец: `node.project_id`, а для shared/global — `author_project_id`
  (хранится в payload и в id не входит). Проверка одна:
  `owned_by(node, caller)` (`models.py`). Подробности — в
  `MEMORY_DEDUP_RU.md`, раздел «Владение и проект вызывающего».
- Legacy shared/global-узлы без автора считаются ничьими, то есть чужими для всех
  проектов. Backfill автора не делается.
- `memory_link` SUPERSEDES разрешён только на узел, которым вызывающий владеет.

## 5. Принятые решения

- AI-ран: модель не может переключить проект. Для `boards_*`/`repo_*` поле
  `project_id` означает проект Azure DevOps, поэтому их это правило не касается.
- Несвязанный MCP-сервер (без проекта) видит всё, как и раньше. Явный
  `project_id` в аргументах MCP переключает проект: это сделано намеренно,
  пользователь сам называет проект.
- Gate действует на каждый вход с проектом: MCP add/bulk/split, авто-запись
  хуков и `capture_memory_turn`, promote, Review Accept и batch, HTTP
  `POST /api/memory`, SDK `add`, Ask-чат. Review Accept берёт проект кандидата.
- Ask-чат без `project_id` пишет в проект по умолчанию `architectos` и выступает
  от его имени.
- `access_count`/`memory_score` общих узлов меняются от чтений всех проектов. Это
  телеметрия, а не мутация gate.

## 6. Открыто (follow-up)

- `_apply_revision_supersede` и HTTP-предпросмотр dedup не проверяют владельца.
- `stable_id` склеивает части через `|`. Метка вида `"…|<caller>:<hex>"` может
  занять солёный id другого проекта: запись тогда отклоняется, перезаписи нет.
  Варианты исправления: адресное экранирование `|` или вторичная соль.
- После commit медленный `embed(v1)` в MCP-процессе может записаться поверх v2
  другого процесса. `ensure_indexed` это потом добирает.
- Мутирующие HTTP-эндпоинты (pin, merge, favorite, promote-long-term) проект
  не проверяют: UI считается доверенным.
- Если авто-запись свернула факт в существующий узел своего проекта,
  `undo_auto_capture` архивирует этот узел. Так было и до изоляции.
- Опциональный backfill автора для legacy-узлов по истории кандидатов.
- Ситуация: голый слот занят чужим узлом, а promote с явным `interface_id` идёт
  с изменённым текстом. Тогда у вызывающего появляется ещё одна своя копия рядом,
  без связи со старой: соль копии зависит от текста. Чужой узел при этом не
  меняется. Вариант исправления: при `replace_own` солить только проектом
  вызывающего.
- Held срабатывает только при совпадении и метки, и текста (exact restatement).
  Если тот же текст пришёл с другой меткой, например голосовая запись без метки
  получает метку из текста, рядом с чужим узлом создаётся новый узел с
  `possible_duplicate_of`.

## 7. Как проверять

Тесты изоляции:

- `tests/test_mcp_server.py`: `ProjectIsolationByIdTests`, `ProjectIsolationReferenceTests`;
- `tests/test_memory_retrieval.py`: `ExplicitScopeNarrowsTests`;
- `tests/test_graph_analysis.py`: `MultiHopExpansionTests`;
- `tests/test_tool_gateway.py`: `ToolGatewayUnitTests`;
- `tests/test_memory_dedup_gate.py`: матрица «вход × случай», `AuthorOwnershipTests`, гонки, отложенные listener-ы;
- `tests/test_memory_capture.py`: `CallerProjectCaptureTests`.

Изменения в этой области считаются изменениями высокого риска: каждое проходит
независимое ревью, полный прогон тестов, а тесты на новое поведение должны падать
на коде до правки.
